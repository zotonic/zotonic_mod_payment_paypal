# Zotonic PayPal payment module

Payment Service Provider module for [zotonic_mod_payment](https://github.com/zotonic/zotonic_mod_payment) using PayPal REST Orders v2.

## Configuration

Configure these module settings in Zotonic:

* `is_live` - set to `true` for the live PayPal environment, `false` for sandbox.
* `client_id` - PayPal REST app client id.
* `secret` - PayPal REST app secret.
* `webhook_id` - PayPal webhook id used to verify webhook signatures.

## PayPal setup

Create a PayPal REST app and configure the webhook URL:

```text
https://example.com/paypal/webhook
```

Subscribe at least to these events:

* `CHECKOUT.ORDER.APPROVED`
* `CHECKOUT.ORDER.COMPLETED`
* `PAYMENT.CAPTURE.COMPLETED`
* `PAYMENT.CAPTURE.DENIED`
* `PAYMENT.CAPTURE.DECLINED`
* `PAYMENT.CAPTURE.PENDING`
* `PAYMENT.CAPTURE.REFUNDED`
* `PAYMENT.CAPTURE.REVERSED`

The checkout return URL is generated by the module as `/paypal/ready/:payment_nr`.


Receiving external payments
---------------------------

With `mod_payment.accept_unknown_payments = true`, verified order/capture
webhooks can import payments without a local reference. The adapter fetches the
current order/capture from PayPal and passes normalized data to
`mod_payment:receive_payment/3`. Related captures use the order identity;
standalone captures use a `capture:` prefix. Refunds resolve the original capture,
so the refund amount is not imported as a new payment. No capture operation is
performed by this path, and no payment-list polling is added.

Account discovery through Transaction Search is opt-in: set
`mod_payment_paypal.enable_reporting_polling = true` only when the API app has
the `https://uri.paypal.com/services/reporting/search/read` permission. It also
requires `mod_payment.accept_unknown_payments = true` and respects
`mod_payment.disable_unknown_payment_polling`. Polling runs every four hours;
reporting can lag by three hours. PayPal webhooks are app-scoped and therefore
do not provide an account-wide payment feed. See mod_payment for checkpoint,
lookback and supported-transaction details.

Returned reporting transactions use `transaction_updated_date` for retention and
reconciliation of known payments. Transaction Search has no separate
modified-since filter, so this does not guarantee discovery of changes to old
transactions outside the search window.
